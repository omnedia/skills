# Omnedia Motion Graphics

Use the exposed Remotion plugin to scaffold projects. This skill is independently installable: copy this complete folder. Keep runs, installed dependencies and generated projects outside the installed skill. Select the single installed style, `editorial-collage`, automatically. Read [its style brief](styles/editorial-collage/STYLE.md) before authoring scenes. Use Remotion only; do not route this workflow to HyperFrames. Target approximately 50% of the video's duration in animation; exceed that when additional passages benefit from visual explanation. Selective placement means purposeful selection, not sparse coverage or a small fixed clip count. Prefer full-frame editorial scenes for selected explanatory passages; choose overlays when preserving the base shot helps.

Every insert must be a Vox-like image collage built from **at least three separately generated scene images**: a contextual background, a subject/midground and a foreground that creates visible overlap. Generate a fresh image set for every animation, including number-led, diagram and paper-note passages. SVG/CSS may supply supporting notes, labels, arrows and highlights; never use them to build the background or scene environment, or as the majority of the visual treatment. A flat generated poster, one hero image over a vector backdrop, or multiple crops of one image do not meet this requirement. Follow the style brief's [image-layer contract](styles/editorial-collage/STYLE.md#required-image-layers) and [coverage and distinctness rules](styles/editorial-collage/STYLE.md#coverage-and-distinctness).

Use the supplied transcript as the content brief. This is an animation workflow, not a fact-checking or source-verification workflow. Do not research whether the speaker's information is verified, add visible source labels or disclaimers, or add phrases such as “laut Sprecher,” “unverified,” or “reported individual example” merely because the content comes from the transcript. Preserve the supplied meaning, numbers, units and spoken qualifiers; do not introduce your own editorial qualifications. Asset filenames and generation metadata belong in the project files, not on screen.

Treat each selected insert as an editorial beat with a smooth entry over footage, meaningful reveal, readable moving hold and smooth return to the base shot. Every insert, including number-led and paper-note treatments, needs a layered parallax environment with motion continuing throughout its visible duration. Animate every element's entrance and departure; no direct pop-ups or frozen reading phases. Follow the style's [motion direction](styles/editorial-collage/motion-direction.md) for transitions, depth and clean annotations. Extend the generated Remotion project when the bundled renderer cannot express the selected treatment. Preserve the original video's unselected passages; a full-frame insert does not imply a fully animated video.

Subjects depicted inside a scene need plausible support, scale and occlusion throughout the camera move. Plan those relationships before assigning parallax depths; follow [logical placement](styles/editorial-collage/motion-direction.md#logical-placement-and-contact) for grounded subjects and connected objects.

## Workflow

For every scene, [generate its separate image assets](references/asset-sourcing.md) using the available image-generation workflow. Missing user-supplied images are not a blocker. If generation is unavailable, preserve the plan and report that blocker; do not substitute SVG scenery or flat slides.

Plan scenes centrally, then delegate independent asset generation **and verification** to parallel sub-agents when available. Read the [worker hand-off](references/asset-sourcing.md#parallel-generation-and-verification) before dispatch. Keep the main agent working on independent preparation while workers run; integrate verified results as they arrive. The main agent owns shared plans and final scene verification. If delegation or concurrent generation is unavailable, use the same briefs and checks sequentially.

1. Resume `run.json` or create it near the intended output. Record input paths, choices, blockers and plugin evidence (`availableInApp`, current `instructionPath`, ISO `checkedAt`). Read [configuration](references/configuration.md). Default to `renderRequested: false`; set it true only for an explicit render/export request in the initial prompt or a follow-up, and record that request. Creating an animation, opening a preview or delivering an editable project does not imply export. Reuse known editor settings and personal defaults. Run `node scripts/motion-graphics.mjs doctor run.json` before project creation.
2. Determine transcript-driven or explicitly standalone timing. Read the complete source and [timing contract](references/input-and-timing.md). Preserve actual word onsets, ends and occurrence indices. No audio analysis, forced alignment, even distribution of cue words, base-footage manipulation or automatic face tracking. Cue-only inputs support an untimed plan; request word timing before synchronized export. Do not silently relabel them standalone.
3. Use default colors unless overrides or a picker are needed. Launch `node scripts/gallery.mjs run.json` when selecting colors. Open its tokenized local URL. While it is open, inspect source timing and assets. Once opened, wait for Save and the `selection-saved` event, reload the run and continue automatically in the same task. Do not end with “tell me when you save.” Missing demonstration video does not prevent selection. Static swatches are not live animation previews.
4. Before designing, inspect the supplied [style preview](styles/editorial-collage/preview.gif) at moments where its scenes are visible; its placeholder frames are not the reference. Use it to establish image detail, background/subject/foreground separation and changing overlaps. Author `scene-plan.json` using [scene planning](references/scene-planning.md). Select useful passages across the complete transcript for approximately 50% coverage or more. Plan each insert's composition, motion progression and separate image briefs before dispatching generation and verification to workers. Continue independent timing, annotation and reusable animation preparation while they run. Integrate each verified image set as it arrives, then finalize its supporting graphics and motion against the actual imagery. Record exact anchors, prepared layers, placement, camera, mode and overrides. In `editorial-plan.md`, compare coverage, fresh image sets, spatial relationships and choreography across all inserts; redesign repeated or flat treatments before production. Use `editorial-scene` or `layered-parallax` as the enclosing scene; compact vector fixtures do not satisfy the image-layer requirement. Supplied masks or a separately available preparation workflow may help; this skill does not implement segmentation or inpainting.
5. Validate with `node scripts/motion-graphics.mjs validate run.json`. Resolve missing assets, unsupported glyphs and timing/layout problems. Simplify or omit graphics that cannot fit, then recalculate coverage and select other useful passages as needed. Do not alter speech timestamps. Check the required generated image layers, visible depth, coverage and distinct choreography separately; the validator cannot assess those visual qualities. Passing compilation is not style acceptance. Preparation runs dependency-free checks; it does not claim to measure fonts.
6. Run `prepare run.json`; use the Remotion plugin to scaffold exactly the allocated `projectPath`, install it, then run `attach run.json` and `dependencies run.json`. See [project/export](references/project-and-export.md). A failed scaffold/attachment resumes at the saved path. Never reattach to overwrite edits.
7. In that generated project, run `npm run motion:compile`. It loads the exact bundled font in the installed renderer, measures complete labels and saves immutable geometry, frame intervals and fingerprints. Record `compilationComplete: true` in the run after success. Errors identify changes needed before rendering.
8. Run `npm run motion:studio` as a persistent process. Wait for its ready URL, then actually open that URL in the available in-app browser (or the system browser if unavailable). Use the current browser tool/skill guidance. The helper's `--no-open` prevents an automatic extra browser window; it does not replace this opening step. Show the `Motion` composition so the user can play and scrub the scenes. Reuse an existing current server; after edits, recompile and restart if it stopped for stale inputs. Keep Studio running and record `studioUrl` and `status: ready-for-review`. Deliver the editable project and browser link. Do not run `motion:render` or `motion:preview` by default.
9. Only when the user explicitly requests rendered/exported files, run `npm run motion:render`. A clear request in the initial prompt is sufficient; do not add another confirmation gate. On a follow-up, reuse this project rather than recreating it. Default export packaging is individual full-canvas MOV clips; use `delivery: sequence` only when requested. After successful export, deliver clips, project, settings, placement manifest and `EDITOR.md`, and record completion. `motion:preview` encodes an MP4 and also requires an explicit request for a rendered preview file; it is not the command for browser review.

## Review and export boundaries

Default delivery is the editable project open in Remotion Studio, with `renderByDefault: false` in saved settings. When export is explicitly requested: silent ProRes 4444 MOV, PNG intermediate frames, `yuva444p10le`, straight alpha; default composition 1080×1920, export scale 2 → 2160×3840. Full-screen inserts are the default for selected passages; save sceneMode, placement and background. Overlays and gaps retain transparent unused canvas. Texture and shadows belong to designed materials. Demonstration backgrounds never enter exports.

Deterministic compilation and opening Studio are required by default. Inspect the existing style GIF before design and use Studio for scene review. This does not authorize video encoding: no automatic final render, preview MP4, frame extraction or post-render visual/alpha/composite/silence checks. Do not substitute a rendered preview for opening Studio or import unrelated diagnostic loops from another video skill.

If plugin/runtime/timing/assets block a step, preserve the run, resolve independent work, state the precise blocker and resume. Do not claim an editor import was tested without performing it. These are rendered assets plus editable Remotion source, not MOGRTs.
