# Omnedia Captions

Create an editable Remotion project and a synchronized transparent caption overlay. Shipped styles are **Active Word Highlight**, **Editorial Kinetic**, **Montserrat Difference**, **Brunson Red Script**, **Vermilion Brush Editorial**, and **Yellow Authority**. All styles default to one transparent MOV; Montserrat offers optional Difference compositing when explicitly requested. This directory is independently installable; the Remotion app plugin and local runtime remain mandatory prerequisites.

## Choose the look

Load [styles/catalog.json](styles/catalog.json). Skip style selection when the request already picks a valid style. Otherwise start `node <skill>/scripts/gallery.mjs <run.json>`, open its exact local URL, and let the user choose. It displays four columns on wide screens, readable smaller layouts, and a selectable placeholder if a GIF is unavailable. Only installed styles appear.

Read only the selected style’s instructions: [Active Word Highlight](styles/active-word-highlight/STYLE.md) [Editorial Kinetic](styles/editorial-kinetic/STYLE.md), or [Montserrat Difference](styles/montserrat-difference/STYLE.md). Editorial Kinetic uses short reviewed phrases, mixed typography, directional group entrances and optional drawn underlines; save phrase grouping and emphasis in per-project options. If colors are unresolved, use the gallery’s role-labeled pickers, visible hex values, brand palette and live sample. The save button writes style, colors and acceptance into the run and prints a `selection-saved` event to the gallery process; read the updated run before preparing the project. With an already selected style, the gallery goes directly to colors. Skip this step when colors are explicit or defaults are clearly accepted. Never infer a highlight role from an arbitrary brand palette entry.

Keep the task active while the gallery is open. Start the gallery in a persistent process session and retain its session ID; opening the browser is an intermediate step, never a reason to send a final response. While the user chooses, do independent work: inspect inputs, review or align word timing, normalize the transcript, and check runtime prerequisites. Defer style-specific grouping, `prepare`, attachment and rendering until selection is saved. When updating the run during this work, reread it and merge only the fields you own so a new browser selection is not overwritten.

After independent work, read the run and poll the gallery process in bounded waits of at most 30 seconds until a new `selection-saved` event arrives. Reread the run to recover a selection if process output was missed; pre-existing accepted colors do not count as a new Save when reopening the picker. Continue progress updates while waiting; do not end the turn with “choose and come back.” Saving a browser form does not itself send a chat message or restart an ended turn. On selection, reread the run, stop the gallery process, and continue through rendering and delivery in this task. If the server exits without a selection, recover the gallery or use the chat fallback. Respect cancellation or a real missing-input blocker; elapsed time never counts as a selection.

If the browser is unavailable, show the actual preview/name in chat, list the style’s color roles/defaults and named brand colors, and accept a named style and explicit role mapping or acceptance of defaults. Save the same fields in `run.json`. Close the gallery server after selection. Missing timing must not erase completed choices.

For Editorial Kinetic, apply the style's [underline selection guide](styles/editorial-kinetic/STYLE.md#choose-by-editorial-purpose) across the transcript before rendering. Save a per-phrase choice: no underline for ordinary text, a curved stroke for quieter editorial emphasis, or a bold bar for major beats. Do not propagate the example's underline setting to every phrase.

For **Vermilion Brush Editorial**, read [its style guide](styles/vermilion-brush-editorial/STYLE.md). Use word timings only; no audio analysis, footage editing, or generated backgrounds. `prepare` persists deterministic phrase/template/role choices in `settings.layoutPlan`, with project overrides kept separately. Automatic font selection targets roughly equal word counts in white Brush Script MT and vermilion Brunson across the sequence, using script for connective phrasing and Brunson for strong anchors. Ordinary captions use the same balance with instant replacements; only readable openings and eligible transcript callouts receive automatic decoration. Explicit overrides can select accumulation or more elaborate layouts. Keep source wording and stable word indices, and reject missing fonts or glyphs.

For **Yellow Authority**, read [its style guide](styles/yellow-authority/STYLE.md), then interpret the complete transcript and author `run.styleOptions.editorialPlan` before `prepare`. Decide phrase boundaries, focal words, typography, placement and motion from meaning and timing, without keyword lists or fixed sentence-pattern triggers. This is the AI's responsibility; do not ask the user to annotate words. Keep ordinary white speech dominant, use yellow selectively, and reserve italics for actual structures. Save all source words in order with contextual reasons for the choices. `prepare` validates and compiles the plan; `captions:plan` loads exact fonts and persists measured geometry before Studio/export. Missing or stale editorial plans fail explicitly. Reconsider choices after text or density changes. Previews use the same AI planning workflow and renderer as ordinary requests; do not force treatments for a showcase.

## Produce and deliver

For **Brunson Red Script**, read [its style guide](styles/brunson-red-script/STYLE.md). Ordinary speech uses instant small white Brunson units. Author hero selection, independent regions and script overlap explicitly; never promote all sentences to animated titles. Use the exact two font files, check their source notices and reject unsupported glyphs rather than substituting. The example timing is a synthetic demonstration, not the reference video's transcript.

Follow [project and export](references/project-and-export.md). Normalize semantically reviewed word timing into the internal Caption representation. Once prerequisites, timing, name and choices are resolved, run `prepare` to select an unused destination and save resolved settings. **Use the available Remotion plugin's creation instructions to scaffold and install a new project in that destination**, then run `attach` to add the caption component, font, data and export helpers. Do this automatically as part of the authorized request. The plugin owns project setup; this skill carries no project template, package manifest, lockfile or installed dependencies. Keep all dependency installations in the generated project, never inside the skill.

Create the animation with Remotion and render the final output directly. Do not run preview renders, frame screenshots, placement reviews, alpha/composite checks, audio-silence checks, or post-render verification as part of normal delivery. Only run a preview or diagnostic when the user explicitly requests it. A successful final render completes the export step.

For every style, including Montserrat, default to one silent caption-only ProRes 4444 MOV with alpha. Montserrat `delivery.mode:alpha` renders source colors normally while preserving its layout and motion. Explain briefly that true backdrop-dependent Difference is optional; do not trigger a delivery questionnaire for an ordinary overlay request. Use its footage/separate-layer workflow only when the user explicitly requests that delivery, preserving the instructions in `EDITOR.md`. Never copy a gallery background or `previewBackground` into an export, or create footage from a gallery color. New projects default to 2× export scale (2160×3840 from the portrait composition), using PNG frames. The saved JPEG quality of 90 applies only to explicitly opaque JPEG workflows; omit it for PNG. Do not bake a checkerboard or audio into the export. A keyable solid background requires an explicit request/editor requirement.

Deliver the single alpha MOV unless footage or separate blend layers were explicitly requested. Include the editable project folder, saved `project.json`, and timeline placement instructions from `EDITOR.md`. Report render failures honestly; deliver once rendering succeeds. Keep personal defaults outside this skill and do not change them for one-off overrides unless asked.
